# Raw Public Window Adapter

`raw_public_windows.py` consumes the formal capture's `trajectory.jsonl.gz`, `events.jsonl`, `run_receipt.json`, and optional `manifest.json`. It reads the trajectory once in gzip order, groups the actor rows for one `(branch, sim_time_s)` tick, and retains at most the requested number of input frames plus one prior tick. The smaller public event log is indexed in memory by branch and visible time so event ordering in that file cannot connect branches or expose delayed events. The adapter emits a transition only for adjacent seconds in the same uninterrupted branch run; a branch switch, time gap, malformed/incomplete actor tick, or duplicate actor row breaks the window history.

The source trajectory is post-step readback at time `t`; emitted inputs therefore represent public state after that second, and the target is the next post-step state at `t+1`. This phase differs from a pre-step decision snapshot. Platform features use actual public position, velocity, remaining energy, aircraft kind/zone, fault state, communication hold, and energy safety pause. The capture format does not include an `available` field or queue snapshot: availability is encoded as value zero with `availability_known=0`, and queue features are marked unknown. An explicitly supplied public boolean availability is encoded as known. Current task IDs are used only to join an actor to an already activated public task. Applied action remains missing because the raw trajectory/event pair does not record an applied command vector; command delivery/result flags are never treated as the action.

The public task manifest is treated as a catalogue only. A task node is created only after a branch-local public `task_activated` event is visible, or from the explicit initial remaining/completed task IDs in a suffix receipt at its declared decision time. Manifest geometry then supplies the activated task's public zone and bounds. Unactivated tasks, evaluator schedules, discovered target IDs, hidden truth, scenario hashes, payload blobs, and future tapes are not read into features. Public observations are deduplicated by their observation identifier for the current frame and included only when `available_at_sim_time_s <= t`; observation and event identifiers remain join metadata and do not enter numeric features.

Normal paired-run `keep`/`replan` branches may not repeat pre-branch `task_activated` events. When `pair_snapshot.sim_time_s` is present, the reader uses only `pair_prefix` activation/completion events visible by that snapshot to seed task-state metadata in both branches. Prefix trajectory frames, positions, energy, event values, hidden truth, and branch outcomes are never copied. Suffix-worker receipts with an explicit initial task list take precedence and are supported at their declared state time.

One-step energy delta uses the mean `energy.remaining_wh` change over the same actor IDs at adjacent ticks. Task completion, risk, and delay targets use branch-local public events with event time in `(t,t+1]` and both event time and availability no later than `t+1`; complete-event masks require a complete actual-ISAAC receipt and a parseable event log. Public safety, boundary, and constraint violations are retained as risk events. Delay additionally requires exactly one visible-by-`t+1` public `transmission_sent` and one `command_applied` for the same aircraft and decision ID; later duplicate commands cannot alter an earlier target's validity. No gain is inferred from branch metrics or long-horizon endpoints. An optional independently validated gain record must exactly match `state_id`, source run ID, phase, branch, and input/target seconds; otherwise `gain=None`.

The focused synthetic gzip test covers raw field mapping, public and pair-prefix task state, delayed observation visibility, one-second energy/event/delay/risk labels, gap and branch boundaries, hidden-field perturbation invariance, availability-known masking, and absence of invented gain. It does not read or train on real trajectories. Training, GPU work, and remote runs remain `NOT_RUN` pending the 30/30 gate. The minimal `FEATURE_NAMES` addition changes checkpoint input shape, so prior world-model checkpoints require retraining or explicit migration.
