# Pre-Candidate Decision Windows

`decision_windows.py` exposes ordinary pre-candidate decision inputs with the independently reduced gain target. It calls `light_models_v1.dataset.load_feature_dataset` first, preserving the existing terminal batch receipt, 168-scene/30-30 summary gate, source-report pairing, split binding, and dataset-level public-projection hash checks. A row is eligible only if that existing loader returned its state ID; this module does not trust a caller-supplied `validated` flag.

For each eligible row, the adapter additionally verifies the `state_index.json` SHA-256 sidecar, exactly one local state entry, the public projection file hash, the decision/projection time, `backend_time_s == decision_time_s - 1`, and the exact `post_public_updates_pre_candidate_generation_pre_step` continuation phase. No private pickle is opened. Index identity fields, hashes, scenario IDs, split, and gain are metadata/labels only; none enter numeric history features.

Input history is streamed from that scene's representative raw trajectory and retained in a bounded deque. The physical history ends at `decision_time_s - 1`; the independently hashed public projection at `decision_time_s` is appended as its own pre-candidate frame. The index's ordinary public trigger event names are attached to that decision frame at the recorded decision time, preserving the public trigger context even though the projection schema has no event field. Histories can be shorter after a gap or near the start of a run. No future frame, paired keep/replan consequence, applied action, or candidate catalog is included. The metadata names both phases and keeps `backend_time_s` distinct from decision time instead of deriving one from the other.

Gain samples and dynamic samples have separate interfaces. `DecisionWindow.gain_target` is the aggregate mean of the independently evaluated suffix `G` values. `iter_raw_dynamic_windows` exposes only genuinely adjacent representative raw physical transitions and the corresponding public event/energy masks; those windows carry no paired gain. Neither interface infers one-second dynamic supervision from a mixed-phase decision history.

The event tensor now uses `EVENT_SCHEMA_VERSION="public_events_v2"` and includes all four ordinary sampler triggers (`task_activated`, `public_observation`, `search_cell_complete`, and `energy_anomaly`), increasing `EVENT_DIM` from 9 to 12. This changes the event-encoder input shape; checkpoints created with the previous event schema are incompatible and require retraining or an explicit migration.

The synthetic focused test checks the label/source/projection identity binding, numeric trigger encoding, backend-time equation, phase and projection-hash rejection, bounded pre-decision history, and invariance to an added post-decision raw tick. It reads no formal batch data and opens no private snapshot. No training, GPU work, deployment, or live-data reads are part of this interface change.
