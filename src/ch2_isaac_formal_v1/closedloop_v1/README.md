# Closed-loop v1

Compare completed, independently reduced episodes using the frozen registration manifest. The comparator reads only registered `episode_reduction.json` files and never launches a simulator or loads private trajectory/evaluator data:

```powershell
python -B -m closedloop_v1.compare_methods --registry <registry.json> --reductions-root <runs-root> --primary-method <registered-method> --output <comparison.json>
```

Pairing uses `scene_id`, falling back to `scenario_id`; `parent_family` is never treated as an independent scene key. Repeated training seeds are averaged within each scene and method, while duplicate or missing pre-registered seeds, missing/invalid reductions, scope mismatches, or unpaired scenes make the comparison inconclusive. Reported confidence intervals are uncorrected scene-bootstrap intervals. Permutation p-values use one Holm family per split across all non-primary methods and available metrics. Numerical thresholds are reported separately and the comparator does not issue a method-support decision. The reducer leaves `safety.all_forced_safety_actions_applied` unknown because fault-related task queue release is not independently observed. Its narrower `safety.pause_resume_actions_applied` field covers configured actor pause/resume evidence, stationary follow-up, and observable command effects; missing evidence remains unknown.

`runtime.py` runs one 90-minute representative episode through the real `formal_collection_v1.isaac_backend.IsaacBackend`, `mission` implementation, and source-kinematic simulation package. From the pilot directory, invoke it with the Isaac source tree and a fresh output directory:

```powershell
python -B -m closedloop_v1.runtime --source-root <isaac-source-root> --output <output-dir> --mode existing_et
```

Available modes are `existing_et`, `periodic`, `risk`, `existing_et_gain_gate`, and `periodic_gain_gate`. The first three are independent trigger comparisons; gain-gated names are explicit combinations. Periodic mode uses 240 seconds. Risk mode opens when the public normalized minimum energy is at or below 25%; the runtime safety reserve remains the frozen config value (10%). The episode writes `trajectory.jsonl.gz`, `events.jsonl`, `evaluator_truth.json`, `manifest.json`, and `run_receipt.json`. `evaluator_truth.json` is an evaluator-side artifact and is never loaded by the policy, trigger, or planner. The runner accepts caller-provided configurations, including evaluation cohorts, but this implementation does not launch heldout evaluation. Heldout execution should wait until the formal decision thresholds and strategy are frozen.

Gain-gated modes require an explicit predictor artifact. MLP checkpoints keep the existing PyTorch `.pt` format; ExtraTrees checkpoints use a trusted Python pickle `.pkl` artifact written by `light_models_v1` and require compatible `scikit-learn` at load time.

```powershell
python -B -m closedloop_v1.runtime --source-root <isaac-source-root> --output <output-dir> --mode existing_et_gain_gate --model mlp --checkpoint <mlp_seed_8201.pt>
```

Use `--model tree --checkpoint <tree_seed_8201.pkl>` for ExtraTrees. Both loaders extract the same ordered public feature schema; the receipt records the selected model and checkpoint hash. MLP inference remains CPU based. No real trained checkpoint has been accepted or exercised by this implementation task.

The WM gain gate uses a separate, paired CLI contract and keeps inference lazy inside the same event-trigger/catalog path. Provide `--wm-checkpoint <wm.pt> --wm-deployment <deployment.json>` with either gain-gated mode; do not combine these with legacy `--checkpoint`. The deployment mode selects its calibrated epsilon. Runtime loading enforces the recorded GPU1 UUID mapped to `cuda:0`; the receipt records that device and load timing. The live bridge retains at most seven public post-step frames and appends the current pre-candidate public projection, matching the trained history phase. Missing or discontinuous history suppresses the ordinary gate with `WM_HISTORY_UNAVAILABLE`; forced safety still bypasses inference. This is only a WM gain gate over the existing catalog adapter. Method E/G-WM, training, heldout evaluation, and live Isaac/GPU execution were not performed.

```powershell
python -B -m closedloop_v1.runtime --source-root <isaac-source-root> --output <output-dir> --mode existing_et_gain_gate --model tree --checkpoint <tree_seed_8201.pkl>
```

`DecisionAdapter` is also the decision boundary for direct use with a live backend. At each simulation decision point, provide the current public projection and newly observed public event names. The adapter reads or accepts the loop's existing `backend.positions()` readback and checks aircraft identity. The planner is lazy: no candidate is built unless the selected trigger opens and, for a gain-gated mode, the predictor allows it. The runner calls frozen `mission.build_public_replan_catalog` only from that lazy callback, then uses the original delayed command queue and stale-action/energy checks.

For task activation, fault, communication hold, energy hold, observation, task completion, or energy anomaly transitions, pass only events already visible to the operational controller. Platform fault and communication/energy safety holds are forced safety overrides in every mode. The episode loop applies fault release, pending-command cancellation, or local hold before constructing the policy projection or invoking the planner. The planner therefore sees the updated public availability and hold state, while any resulting command still enters the original delayed queue. Forced events bypass the predictor. They do not increment ordinary event-trigger state. Repeated ordinary event names are counted individually, matching the frozen `EventTriggerGate` behavior. The low-energy threshold is an ordinary `risk` mode trigger, not a forced safety override, and does not affect the `existing_et` or `periodic` comparison groups. The runner loads evaluator schedules and private truth only for simulation and evaluator outputs; the decision projection contains current public state and no future schedule or truth.

`apply_transfer` implements the existing reconstruction rule: only an unstarted task can move, it is removed from the donor and appended to the recipient, and its public route is copied. The episode runner retains the frozen runtime's command delay/drop queue, energy accounting, safety checks, step timing, and raw trajectory output. Receipt timing divides each tick into sequential event/state/safety, projection/policy/planning, command-ready, and post-step online state phases, each with wall and process CPU duration; their online phase totals do not overlap. Evaluator/telemetry bookkeeping, raw trajectory/event serialization, timing-record writes, periodic flush/fsync, and simulator stepping are timed separately. Startup/load is measured through the first representative tick, and backend close is measured separately. Newly generated replans use projection/policy/planning plus command-ready wall time, rounded up to the 1-second simulator clock and bounded by configured minimum delay. Nested adapter diagnostics are not summed again. The 1-second clock means this runner does not establish millisecond-scale responsiveness. Episode wall time, process CPU time, and peak RSS are recorded in the receipt.

This runner produces one policy episode, not a paired keep/replan evaluation or scientific efficacy result. The copied runtime retains source target truth internally for the mission's simulated sensor predicate and outcome counters; policy, trigger, and planner inputs receive public state only. No Isaac run or holdout evaluation was performed during implementation.

Reduce a completed output directory from its raw trajectory, event stream, manifest, and evaluator truth:

```powershell
python -B -m closedloop_v1.evaluate_episode --run-dir <output-dir> --output <output-dir>/episode_reduction.json
```

The reducer recomputes discovery geometry, analytical energy, ordered sweep completion, objective terms, event counts, and per-tick timing from those artifacts; it does not use runtime summary metrics as reference values. Sweep completion is replayed per actor and task in frozen waypoint order, advancing at most one waypoint per tick with the frozen tolerance. Decision effect-delay output reports created/finalized counts, coverage, missing/orphan/duplicate IDs, and invalid delays; any incomplete coverage makes the delay series `unknown` and the overall reduction `UNKNOWN`, while locally valid `J_exec` remains reported. Stationary fault/communication holds, post-energy-hold motion, actor type/home-zone identity, and helicopter home-zone bounds are independently checked against trajectory and manifest evidence. Runtime timing separates mutually exclusive online decision and post-step state phases from simulator stepping, evaluator bookkeeping, artifact logging, timing-record writes, flush/fsync, startup/load, and backend close. The measured online method cost applies the user-plan CPU coefficient of 0.01 per second to the four online phases only; it replaces the nested planner CPU term rather than adding it twice. Simulator and offline evaluator/evidence-logging CPU/wall remain in a separate resource ledger and are not charged to method cost. Startup/load is reported separately. Feature extraction and predictor inference are included in projection/policy/planning when a predictor is used. GPU inference and host-device transfer are `not_applicable` only when the receipt explicitly records CPU or no predictor; absent device evidence is unknown. Physical transmission cost is not modeled by the simulated command queue. Python process launch/import, final receipt self-persistence, and compressed stream close remain unmeasured offline boundaries, not additions to the measured online method subtotal. A `PASS` status validates episode physical evidence only and does not certify method-cost acceptance. The keep-minus-replan increment remains `unknown` for a single representative episode. `J_exec` uses the frozen `formal_evidence_v1/evaluate_suffix.py` weights. `search_strike` returns `J_exec: unknown` until service dwell is independently replayed. The 1-second simulator clock remains the resolution for effect-time reporting and does not establish millisecond responsiveness.
