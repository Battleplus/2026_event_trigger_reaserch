# V4 Dynamic World Model and PPO Protocol

Status: implementation is in progress. Scenario identities and fixture checks may be prepared before collection. `collect` requires a primary-agent read-only environment review bound to the exact source identity and this protocol digest. No collection or performance result is claimed until its stage writes a receipt.

## Frozen registry

The train and validation registries reuse the existing `v3_shards.expected_registry` identities exactly: twelve replicates for each of seven V3.3 conditions, fixed to `search_rescue` and three targets per region (84 parents per split). The sealed test registry contains 140 scenarios: twenty distinct seeds per condition, also fixed to `search_rescue` and three targets. Every complete scenario identity and content hash, including the event tape, is generated and persisted in `FROZEN_REGISTRY.json` before collection. Test identities remain separate from training and validation.

World-model and policy seeds are 8201, 8202, and 8203. Branching uses seed 842701. Changing these identities requires a protocol version change before new collection.

## Collection

Collection uses one CPU thread while retaining CUDA availability for later training. Each train and validation parent receives three 90-minute trajectories: `periodic_public_best`, `event_public_best`, and `random_legal`. Every minute persists the public observation before and after the complete legal action, its legality and current-time safety receipts, reward, reward primitives, reward terms, and raw events. Public-best actions are chosen from the existing legal public reconstruction catalog using `estimate_public_remaining_cost`; event choices use the existing public `TriggerEngine`. Neither reads the event tape.

Before each source trajectory starts, at most eight distinct branch minutes are sampled uniformly without replacement from the legal horizon using its fixed seed, and then sorted. At each selected minute, one live snapshot is deep-copied into paired branches with the same event tape and safety state. Candidates are NOOP, deterministic public-best (deduplicated if identical to NOOP), and up to two distinct legal actions sampled with a fixed seed from the current legal catalog. Branch horizon is ten minutes. The selected action is submitted once; its queue and dispatch effects persist in the simulator while current-time safety dispositions continue each minute. Each minute records the full action and public transition. Sample identities include source policy and branch minute.

Inputs to `v4_models` contain only up to four public observations and the complete candidate action. Truth and hidden future fields are excluded. Samples include every source trajectory's public one-step transitions and ten-minute paired branches. One-step samples carry only public per-entity next-minute targets; all ten-minute scalar targets are explicitly invalid. Branch targets include per-entity first-minute position, energy, and task-progress changes, plus ten-minute progress delta, deadline delay using actual completion times, incremental task-failure rate, energy, and communication-risk outcomes. Unavailable or masked targets stay invalid. Reward primitives and action outcome costs are independently recomputed by `event_oracle` and `cost_accounting` from raw branch traces; their recomputed values are stored beside the trace.

## World model

The dynamic world model uses two relational graph layers of width 64, a four-frame GRU of width 64, and action records pooled onto the variable platform/task graph. Dispatch and queue-operation counts are aggregated dynamically. Three models use Adam at 0.001, batch size 8, at most 100 epochs, and patience 10. Feature normalization is fit on train samples only. Training requires CUDA; inference uses CPU. Checkpoints bind architecture, normalization, optimizer, RNG states, and training data identity.

Report ensemble metrics against persistence and public-kinematics baselines on validation and sealed test data. Include each head's valid sample count and masked metric. Sealed-test transition metrics are computed only after policy freeze, from frozen-test transitions; report their coverage and do not use test data for training, normalization, calibration, or model selection. Do not impute missing labels. Training reads per-scenario sample shards through a bounded cache; normalization and source identity are computed incrementally.

## PPO and evaluation

Train the seven variants listed in `configs/V4_CONFIG.json` with paired seeds. World-model parameters remain frozen during PPO. Every WM variant feeds action-conditioned predictions to its actor; the critic remains public-state based. `Event-G-WM-Decision` uses WM predictions for action decisions while keeping the public event trigger, `NoU` removes uncertainty from the trigger score, and `Global` removes local-priority preference. Evaluation pairs every method and training seed on the same frozen 140 test scenarios. Analysis averages the three paired training-seed repeats within scenario, uses 10,000 scenario bootstrap replicates and paired permutation, and applies Holm correction across seven preregistered contrasts (reference -> method): Periodic-G -> Event-G; Periodic-G -> Periodic-G-WM; Event-G -> Event-G-WM-Decision; Periodic-G-WM -> Event-G-WM-Decision; Event-G-WM-Decision -> Event-G-WM; Event-G-WM-NoU -> Event-G-WM; and Event-G-WM-Global -> Event-G-WM. Positive cost benefit means reference cost minus method cost. The completion noninferiority endpoint is priority-weighted completion, whose paired 95% confidence interval lower bound must be strictly above -2 percentage points. Direct safety guardrails require 100% forced safety handling and zero newly introduced controllable hard-constraint violations; failure outcomes are secondary. A supported cost claim requires the 95% benefit interval to be above zero, Holm-adjusted p below 0.05, and both safety guardrails plus completion noninferiority. Do not make superiority claims without that analysis.

## CLI stages and evidence

`environment-check` freezes the registry and runs one public branch fixture plus a full 36-platform, 90-minute NOOP run on a compound scenario, recording actual platform-failure and communication events and a live communication pause/release receipt. It also clones a live scenario, changes only hidden future event data, and verifies that the current public observation, public history, and fixed public decision are unchanged. `collect` refuses to run without `environment_review.json` containing status `approved_read_only`, the reviewed source identity including data/oracle/split generators, and the exact protocol SHA-256. `train-wm`, `train-ppo`, `evaluate`, and `analyze` each require their actual input artifacts and write stage receipts. Collection writes one durable shard per scenario. Until a stage has completed, its state remains `NOT_RUN` in `STATUS.md`.
