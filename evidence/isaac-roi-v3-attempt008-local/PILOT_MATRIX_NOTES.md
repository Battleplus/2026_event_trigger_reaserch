# Pilot Matrix Notes

The local generator creates 36 proposed configs: `search` and `search_strike`, target loads 1/3/5, and six fixed seeds (20261101-20261106). Their design status is configuration proposal pending review. Each seed is assigned exactly one condition: light observation delay, task activation, platform fault, energy anomaly, communication outage, or environment speed block. The same seed is shared across all modes and loads to preserve deterministic ROI placement and nested target truth. Seeds 20261101-20261103 belong to `train_dev`; 20261104-20261106 belong to `val_dev`. All six mode/load runs for a seed share its `parent_family`.

Run `python development/ch2_isaac_roi_mission_v3_pilot/pilot/build_pilot_matrix.py` from the repository root to regenerate `pilot/matrix/pilot_matrix.json` and its configs. Paths in the matrix are relative to `pilot/`; each entry records its config hash and the attempt008 source config hash. All entries are `NOT_RUN`, with prerequisite `attempt008 validation pending`.

The generator only expresses controls already present in `run_a1.py`. Disabled hard-coded fault and outage times are set to 6000 seconds, beyond the 5400-second representative episode and the 4800-second paired prefix plus two suffixes. A task-activation condition schedules the fixed 81 public cell tasks at 600 seconds; all other configs clear those lists and therefore use immediate activation. Energy anomaly is null unless selected. Both pilot and scene speed-block lists are empty unless the environment condition is selected.

The light-delay condition changes public observation delay from 1 to 5 seconds. The runner's command delay (2 seconds) and deterministic dropout probability (0.03) are shared baseline settings and are not independently varied. The environment condition reproduces the existing local block; its actual actor exposure depends on aircraft position and is not guaranteed by config alone. No claim is made that the selected environmental condition necessarily activates during a run.

The 36 configs are an engineering coverage pilot proposal: condition type, seed, and development split are bound together, so the matrix cannot support claims about generalization or relative training quality. The formal seven-condition study still needs independent train/validation scenes within every condition. The requested pilot acquisition workflow is also not implemented: the current runner supports one snapshot; it does not capture up to 8 ordinary states and two suffixes per state. The matrix metadata marks this capability blocked. The one focused local test checks the 36 unique mode/load/seed combinations, condition isolation, split/family assignment, and same-seed ROI/target nesting via the fixed public cells and deterministic target coordinates. This matrix has not been executed in Isaac. Attempt008 validation remains a prerequisite; no remote run or training was performed.
